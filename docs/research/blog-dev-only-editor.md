# How the local-only Blog editor stays out of production

Research for ticket 112 (map 109). Question: the editor route and its write server
functions must exist under `bun run dev` and be **absent** from the production build and
server, not merely hidden. What does the installed TanStack Start offer, what actually
ships in `vite build` output for each approach, and how does the checked-in
`src/routeTree.gen.ts` behave?

Installed versions the experiments ran against: `@tanstack/react-start` 1.168.52,
`@tanstack/start-plugin-core` 1.171.42, `@tanstack/router-plugin` 1.168.37,
`@tanstack/router-generator` 1.167.35, `@tanstack/react-router` 1.170.35, Vite 8.3.0,
Bun 1.4.2.

## Recommendation

**Exclude the editor's route files from file-based routing when Vite's command is
`build`**, using the router generator's `routeFileIgnorePattern`. The route files are
the only importers of the editor component and of the write server functions, so
removing them from the route tree removes the whole subgraph: no route, no editor
chunk, no CodeMirror, no server-function registration.

```ts
// vite.config.ts
export default defineConfig(({ command }) => ({
  resolve: { tsconfigPaths: true },
  plugins: [
    tailwindcss(),
    tanstackStart({
      router: {
        routeFileIgnorePattern:
          command === "build" ? "^blog\\.write\\b" : undefined,
      },
    }),
    viteReact(),
  ],
}));
```

`^blog\.write\b` covers `blog.write.tsx` and any later `blog.write.$slug.tsx`. The
pattern is matched against each file or directory **name** in `src/routes`, not its
path (`getRouteNodes.ts`, see Sources).

Two rules make the exclusion hold, and one line proves it on every deploy:

1. **Write server functions live in a file that only editor code imports** (for example
   `src/projects/blog/editor.fn.ts`), never beside a public read function. Registration
   is per compiled *file*, not per referenced export (experiment E below): a write
   function that shares a file with `listArticlesFn` ships as a callable endpoint even
   though nothing in production imports it.
2. **Each write handler starts with `if (!import.meta.env.DEV) throw ...`.** One line.
   If rule 1 is ever broken, the handler body and its database import are still
   dead-code-eliminated (experiment A), so the leaked endpoint can only throw.
3. **The Dockerfile asserts absence** right after `RUN bun run build`:

   ```dockerfile
   RUN ! grep -rqE "editor\.fn|ArticleEditor" dist
   ```

   On the clean build this grep exits 1 (no match); on the leaking build of experiment E
   it matches `./assets/editor.fn-CIfv8irT.js` in `dist/server/server.js`, which would
   fail the deploy. The exact strings follow whatever the editor files end up being
   called.

Cost: about four lines of config, one guard line per write handler, one Dockerfile line.
No per-route boilerplate; editor routes are written like any other route.

### The known wart: `routeTree.gen.ts`

The generator runs in Vite's `configResolved` hook for both `dev` and `build`
(`router-generator-plugin.ts`) and writes the checked-in `src/routeTree.gen.ts` either
way. With the recommendation:

- `bun run dev` writes a tree **with** `/blog/write`. This is the version to commit:
  `createFileRoute("/blog/write")` only typechecks against it.
- `bun run build` rewrites the file **without** `/blog/write`. Measured: after a local
  build the file is dirty in `git status`, and `bun run check` fails with

  ```
  src/routes/blog.write.tsx(4,38): error TS2345: Argument of type '"/blog/write"' is
  not assignable to parameter of type 'keyof FileRoutesByPath | undefined'.
  ```

  Starting `bun run dev` regenerates the correct tree (verified with `diff`: identical
  to the tree that contained the route before the build, Start footer included).
- CI is unaffected. The `check` job in `.github/workflows/ci.yml` runs `bun run check`
  without building, and the production build happens inside the Docker build on Fly,
  where a rewritten tree is thrown away with the build stage.
- The failure is loud and self-correcting: a tree generated by a production build can
  never be committed green, because `tsc` rejects the editor route file against it.

Do **not** use `bun run generate-routes` (`tsr generate`) to restore the tree: it reads
`tsr.config.json`, not the Start plugin config, and drops the Start-specific footer
(`declare module '@tanstack/react-start' { interface Register { ssr: true; router: ... } }`)
that the Vite plugin appends. This is true of the repo today, independent of the Blog.

The wart can be removed (experiment F) at the price of more machinery; not recommended
unless the flip proves annoying in practice.

## Runner-up

**A stub route with a `DEV`-conditional lazy import** (experiment D). It also ships no
editor code and no write endpoint, and the route tree is identical in dev and build. It
lost because:

- `/blog/write` still exists in production as a matched route (in the client route
  table and the Start manifest) whose `beforeLoad` throws `notFound()`: hidden, not
  absent.
- The guarantee rests on discipline in every editor route file. The route file may not
  statically import the editor component **or any editor `.fn.ts`**: one static import
  (a loader that reads a Draft through a server function, say) silently re-registers the
  endpoints. Every such use needs its own `import.meta.env.DEV ? await import(...) : ...`.
- More code per route (lazy wrapper, ternary, `beforeLoad`) versus zero.

## How server functions reach the production server

The production server resolves `POST /_serverFn/<id>` through a generated manifest in
`dist/server/server.js`. Baseline build of `main`:

```js
//#region \0%23tanstack-start-server-fn-resolver
var manifest = {
	"3a2789f8...c403cc": {
		functionName: "listNotesFn_createServerFn_handler",
		importer: () => import("./assets/sticky-notes.fn-CRmTxTSX.js")
	},
	"a651d74e...c76193": {
		functionName: "addNoteFn_createServerFn_handler",
		importer: () => import("./assets/sticky-notes.fn-CRmTxTSX.js")
	}
};
async function getServerFnById(id, access) {
	const serverFnInfo = manifest[id];
	if (!serverFnInfo) throw new Error("Server function info not found for " + id);
```

**An id in this manifest is a callable endpoint; an id not in it is not.** The manifest
is filled by the Start compiler as it transforms each module in the build's module graph
(`handleCreateServerFn.ts` collects every `createServerFn` in the file into
`serverFnsById` and reports them via `onServerFnsById`). So "is there a write endpoint in
production" reduces to "did any module in the production graph contain the write
function's `createServerFn` call".

## Experiments

Throwaway files (none committed):

- `src/routes/blog.write.tsx`: `createFileRoute("/blog/write")({ component: ArticleEditor })`
- `src/projects/blog/ArticleEditor.tsx`: mounts a real CodeMirror (`codemirror` 6.0.2,
  `basicSetup` + `EditorView`, doc `"MARKER_EDITOR_COMPONENT"`) and calls
  `useServerFn(saveArticleFn)`
- `src/projects/blog/editor.fn.ts`: `saveArticleFn = createServerFn({ method: "POST" })`
  whose handler logs `"MARKER_HANDLER_BODY"` and calls `saveArticle`
- `src/projects/blog/editor.server.ts`: `saveArticle` imports `db` from
  `@/db/index.server` and logs `"MARKER_SERVER_HELPER_WRITE"`

After each `bun run build`, `grep -rl <marker> dist/server dist/client` plus the manifest
block above. `cm-editor` is a CSS class string from CodeMirror's own source, so it marks
the dependency itself. The write function's id was
`afb6912d77d0fe92045713729eb0fdb7bb39216344419a73596700cd61c12bd8` throughout.

| | Approach | Write fn in manifest | Handler body / db helper in server | Editor + CodeMirror in client | `/blog/write` route in prod | Build rewrites `routeTree.gen.ts` |
|---|---|---|---|---|---|---|
| 0 | Control, no guard | yes | yes | yes, 382.65 kB chunk | yes | no (same tree as dev) |
| A | Guard in handler | **yes** (throws) | no | yes, 382.65 kB | yes | no |
| C | `beforeLoad` notFound + guarded handler | **yes** (throws) | no | yes, 382.65 kB | yes (404s) | no |
| D | C + `DEV`-conditional lazy import | no | no | no | stub (404s) | no |
| **B** | **Ignore pattern when `command === "build"`** | **no** | **no** | **no** | **no** | **yes** |
| E | B, but write fn shares a file with a public read fn | **yes, fully live** | **yes** | no | no | yes |
| F | B + separate build tree + alias | no | no | no | no | no |

Baseline for size: `main` builds to `dist/client` 1,475,667 bytes, largest chunk
`index-DEEu5E4Z.js` 339.91 kB.

### A. Guard inside the handler

```ts
.handler(async ({ data }) => {
  if (!import.meta.env.DEV) throw new Error("MARKER_GUARD_THROW");
  console.log("MARKER_HANDLER_BODY");
  return saveArticle(data.title);
});
```

Vite does eliminate the body **and** the now-unused `editor.server` import. The whole
server chunk becomes:

```js
var saveArticleFn = createServerFn({ method: "POST" }).validator((input) => input)
  .handler(saveArticleFn_createServerFn_handler, async ({ data }) => {
	throw new Error("MARKER_GUARD_THROW");
});
```

`process.env.NODE_ENV === "production"` produces the identical output: Start statically
replaces `process.env.NODE_ENV` in server builds by default (environment-variables guide,
"Static `NODE_ENV` Replacement"). Either spelling works; `import.meta.env.DEV` is the
Vite-native one.

But the id **stays in the manifest** (a callable endpoint that throws), the route stays,
and the whole editor with CodeMirror still ships to the client (`blog.write-*.js`,
382.65 kB). Fails "absent, not merely hidden" on its own. Useful only as the second layer
under B.

### C. `beforeLoad` notFound plus guarded handler

```tsx
export const Route = createFileRoute("/blog/write")({
  beforeLoad: () => {
    if (!import.meta.env.DEV) throw notFound();
  },
  component: ArticleEditor,
});
```

Same build output as A: endpoint registered, 382.65 kB editor chunk emitted and listed
in the Start manifest for the route. The route merely 404s. `beforeLoad` hides; it does
not remove, because the static `import { ArticleEditor }` keeps the subgraph reachable.

### D. C plus a `DEV`-conditional lazy import (runner-up)

```tsx
const ArticleEditor = import.meta.env.DEV
  ? lazy(() =>
      import("@/projects/blog/ArticleEditor").then((m) => ({
        default: m.ArticleEditor,
      })),
    )
  : () => null;
```

The dynamic `import()` is in a dead branch, so the editor, CodeMirror and `editor.fn.ts`
never enter the graph. All markers absent from both bundles, manifest has no
`saveArticleFn`. What remains is a stub:

```js
//#region src/routes/blog.write.tsx?tsr-split=component
var ArticleEditor = () => null;
```

plus `/blog/write` in `dist/client/assets/index-*.js`, `dist/server/assets/router-*.js`
and the Start manifest. Route tree is the same in dev and build. See "Runner-up" for why
it lost.

### B. Ignore pattern when `command === "build"` (recommended)

Config as in "Recommendation", with the route file and the **unguarded** control server
function, to show exclusion alone is sufficient:

```
== MARKER_HANDLER_BODY        server:   client:
== MARKER_SERVER_HELPER_WRITE server:   client:
== MARKER_EDITOR_COMPONENT    server:   client:
== saveArticleFn              server:   client:
== blog/write                 server:   client:
== cm-editor                  server:   client:
manifest: listNotesFn, addNoteFn only
dist/client 1,475,667 bytes; largest chunk index-DEEu5E4Z.js
```

The client output is **byte-for-byte the baseline**: same total size and the same content
hashes (`index-DEEu5E4Z.js`, `note-render-BJOyM-LO.js`, `StickyEditor-BJR0X-fg.js`) as a
build of `main` with no Blog files at all. Module counts confirm it: 277 client modules
versus 295 in the control.

Runtime check against `bun run server.ts` on that build:

```
GET  /blog/write                         -> 404
POST /_serverFn/afb6912d...  (same-origin) -> 500
  server log: error: Server function info not found for afb6912d...
POST /_serverFn/a651d74e...  (addNoteFn)   -> reaches input deserialisation
```

(Without an `Origin`/`Referer` matching the host, Start answers any `/_serverFn` POST
with `403 Forbidden` before the lookup; that is its built-in same-origin check, not
evidence about the manifest.)

Under `bun run dev` the same config serves the editor: `GET /blog/write -> 200` with the
component server-rendered, and the generated tree contains the route.

### E. The trap: a write function sharing a file with a public one

B's config, but `editor.fn.ts` also exports `listArticlesFn`, imported by a public
`src/routes/blog.index.tsx` loader. Nothing in production imports `saveArticleFn`:

```
== MARKER_HANDLER_BODY        server: dist/server/assets/editor.fn-CIfv8irT.js
== MARKER_SERVER_HELPER_WRITE server: dist/server/assets/editor.fn-CIfv8irT.js
manifest:
	"49e6b3f5...": { functionName: "listArticlesFn_createServerFn_handler", ... editor.fn-CIfv8irT.js },
	"afb6912d...": { functionName: "saveArticleFn_createServerFn_handler",  ... editor.fn-CIfv8irT.js }
```

A fully live, unauthenticated write endpoint. Server functions are not tree-shaken by
export: compiling the file registers every `createServerFn` in it. Moving
`listArticlesFn` to its own `articles.fn.ts` restores the clean result (manifest:
`listArticlesFn`, `listNotesFn`, `addNoteFn`; all editor markers absent). This is why the
recommendation carries rules 1 to 3 and not the config alone.

### F. B without the route-tree flip (not recommended)

```ts
export default defineConfig(({ command }) => {
  const isBuild = command === "build";
  return {
    resolve: {
      tsconfigPaths: true,
      alias: isBuild
        ? [{
            find: /^\.\/routeTree\.gen$/,
            replacement: fileURLToPath(
              new URL("./src/routeTree.build.gen.ts", import.meta.url)),
          }]
        : [],
    },
    plugins: [
      tailwindcss(),
      tanstackStart({
        router: isBuild
          ? { routeFileIgnorePattern: "^blog\\.write\\b",
              generatedRouteTree: "routeTree.build.gen.ts" }
          : {},
      }),
      viteReact(),
    ],
  };
});
```

Works: same clean output as B, and the build leaves `src/routeTree.gen.ts` untouched. But
it needs the alias (because `src/router.tsx` imports `./routeTree.gen`), and the second
generated file in `src/` would then need a `.gitignore` entry, a Biome ignore entry and
most likely a `tsconfig` exclude, since it redeclares `FileRoutesByPath` (those three
follow-ons are inferred, not measured). Roughly fifteen lines across four files to avoid
restarting `bun run dev` after a rare local build.

## Other framework options considered, not built

- **Virtual file routes** (`router.virtualRouteConfig`, conditional on `command`). Same
  generator, same single output file, so the same route-tree flip as B, but every route
  in the app must then be enumerated in a config file. Strictly more code than one
  ignore pattern.
- **`routeFileIgnorePrefix`** (default `-`). Static, not conditional: a `-` file is
  ignored in dev too, so it cannot express "dev only". Making the prefix itself
  conditional would un-ignore every colocated `-` file in dev.
- **A separate Vite `--mode`**. `command === "build"` already distinguishes the only two
  cases this repo has (`vite dev`, `vite build`); a custom mode adds a flag to remember
  and a way to build production with the editor in.
- **Import protection** (`tanstackStart({ importProtection })`). Guards which
  *environment* (client or server) may import a file; it has no dev-versus-build axis.
- **A second Vite app / entry for the editor**. Would work and needs no conditional, but
  duplicates router, styles and the Article renderer wiring that the preview is required
  to share.
